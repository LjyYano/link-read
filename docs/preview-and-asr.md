# 链接预览与无字幕语音识别

## 1. 链接预览

Apple Podcasts 支持含 `i=` 的单集链接。预览直接读取该单集的公开页面并精确核对节目与单集编号，不先拉取节目最近 200 集，也不按相似标题或第一条结果选择。预览仅请求 Apple 元数据，不下载 RSS、字幕或媒体。后端预览有 8 秒总预算，包含 DNS 与正文读取；原生进程另有 15 秒截止。生成也优先读取单集页面，但保留常规网络等待预算，慢网下预览超时不会强制让生成也在 8 秒内失败。仅页面结构不兼容时回退 Apple Lookup，订阅、权限或网络错误不会触发回退。封面仅允许 Apple `*.mzstatic.com` CDN。

粘贴完整的 YouTube / B 站视频或 Apple Podcasts 单集链接后，输入停顿 200 毫秒再请求元数据，输入框下展示封面、标题、作者与已知时长。视频封面使用 16:9，播客使用真正的 1:1 容器，避免两侧留白。不查询字幕、不下载音轨、不调用大模型。YouTube 使用轻量 oEmbed，未提供时长时不编造时长。B 站支持 BV、分 P、带 `bvid` 的稍后再看链接及受限跳转的 b23.tv 短链接。可以直接粘贴“分享标题 + 链接”、Markdown 链接或带反斜杠转义的链接。三个入口（前端、Rust、Python）共用一组规范化用例；移除跟踪参数但保留分 P，查重始终使用同一个视频标识。多个不同链接会明确拒绝，不猜测用户要处理哪一个。

修改或清空输入会立即使上一请求失效；迟到的结果不能覆盖新链接。客户端最多缓存 32 条结果、有效期 10 分钟；缓存键包含地区与单集，同一链接的进行中请求合并。清空输入只取消当前订阅，不丢弃随后到达的有效缓存。等待 4 秒后显示慢请求提示，12 秒后结束加载并提供重试，重试不叠加尚未结束的同链接请求。获取失败不禁用生成按钮。提交时将匹配当前链接的预览信息带入任务；播客生成取得元数据后立即更新任务标题、时长和封面，无需等字幕或 ASR 完成。

## 2. 开启 ASR

设置中打开「无字幕时使用语音识别」，默认关闭。第一版接入阿里云百炼 `paraformer-v2`，使用**原生 HTTP 异步文件识别 API**，不是 OpenAI 聊天兼容接口。

- Token 独立保存到本机私有文件；只有显式勾选「复用已保存的自定义 API Token」才共用聊天凭证。不会因选择 Codex 自动复用其他供应商的 Key。
- 北京默认 API 地址 `https://dashscope.aliyuncs.com/api/v1`；高级设置支持北京 workspace 专属域名 `https://<WorkspaceId>.cn-beijing.maas.aliyuncs.com/api/v1`，以及 `https://dashscope-intl.aliyuncs.com/api/v1`。不同区域需对应的 Key。
- 测试按钮使用百炼官方约 4 秒语音样本进行一次实际转写，可能产生少量费用。验证模型调用而不是仅检查网络连接。它不验证用户视频下载权限。
- 默认单次时长上限 120 分钟，可在高级设置设为 1–720 分钟；单个音频上传上限 200 MB。分片模式下完整音轨下载上限为 2 GiB，整段模式为 200 MB；本地 PCM 分片前会检查磁盘空间。无法确认时长时停止，不自动下载未知长度直播。

开启并配置 ASR 后，提取器确认无可用字幕时可以继续转写。B 站播放器明确要求登录查看字幕且未提供可用字幕地址时，生成会自动尝试公开音轨，无需再次确认。网络错误、损坏字幕、音轨权限错误和受保护音源都会停止处理。仅处理用户有权访问和使用的内容，不读取浏览器 Cookie、不绕过登录、付费或 DRM。

## 3. 数据与恢复

`检查字幕 → 下载完整纯音轨 → 超过分片阈值则本地切片 → 上传与转写（最多并发 2 片）→ 时间戳合并 → 原有 AI 整理和阅读页`

仅选择 `bestaudio`，没有独立音轨就报错，不静默下载视频画面。

高级设置默认按 **5 分钟**分片，也可选择 10 / 15 分钟或“整段转写”。超过阈值需要本机 FFmpeg；无需 Homebrew：在 App 设置的本地环境区点击「选择 FFmpeg…」，选择已解压的程序。还未安装时使用 [FFmpeg 官方下载页](https://ffmpeg.org/download.html) 中的 macOS 预编译版本链接，解压到固定目录后选择，不能选择压缩包或源码目录。App 不会自动下载或运行安装脚本。

本地检查会确认程序文件及执行权限，运行 `-version` 校验身份与版本，限制输出大小并在 5 秒内结束；不上传音频、不使用 ASR Token。所选路径随设置保存，生成任务明确传递给视频/播客下载前检查及音频分片，不修改全局 PATH。原生层将所选路径传给本仓库的 Python 后端。未找到所选 FFmpeg 时，在下载长音轨前给出提示，不静默切换收费策略。短音频及整段转写保留原有的直接上传方式，不依赖 FFmpeg。已提交的云任务和成功片段仍优先恢复，修改本机 FFmpeg 路径不会创建新的计费身份。

分片把解码音频转成 16 kHz 单声道 PCM WAV，按约 5 分钟切分。最后不足 5 分钟的一片也会处理。句子时间戳由服务端提供，再加上**实际 WAV 样本数计算的片段起始偏移**；不根据文字长度估算，也不删除不同时间真实重复的句子。纯静音分片也会记录已完成，避免反复收费。固定边界可能影响跨片句子的识别连贯性，当前未做语音活动检测切点。

这不是边下载边转写：目前先下载完整音轨再切片，不会节省这次完整音轨的下载量。分片提高可恢复性并允许有界并发，不承诺总费用降低或任意视频都更快。

ASR 的句子时间戳直接来自服务端，不按字数估算。新转写文档使用 `schema_version=1.1`、`transcript_source=asr`；旧版 1.0 文件仍可读取。HTML 明确标注语音识别稿可能存在听写错误。

资料库 `.asr/` 中保存阶段缓存，按视频、API 地址、模型和凭证指纹隔离，不保存明文 Token。每个分片独立保存任务 ID、音频校验和和完整句子结果；重试复用成功片段，继续查询已提交但未结束的云任务。修改分片长度后，仍优先完成上一次已有收费任务的分片计划，避免再次提交。旧版已经提交的整段任务也优先恢复，不因默认分片升级而重复转写。成功转写后保留字幕、清理本地音频及 PCM 分片。后续 AI 阶段失败不会导致再次转写。等待网络中断后继续查询相同云任务，不重复提交。明确的服务端失败允许用户手动重试；提交请求结果不明时停止自动提交，避免重复计费。

取消本地任务会停止下载/等待进程，但**已提交的云端任务可能继续执行和计费**；再次尝试会使用保存的任务 ID。应用不承诺撤销云端运行中的任务。

## 4. 临时存储限制

本次实现使用百炼官方临时上传接口，为**个人本地低频测试版本**。远端音频 48 小时后自动清理，不能保证用户取消后立刻删除。官方不建议将临时 URL 用于生产环境；产品正式分发/生产部署前应提供用户自有 OSS 的私有存储及签名 URL 策略。本次没有默默创建公开 Bucket，也没有使用第三方临时文件托管网站。

API Token 只发送给允许的百炼 API 域名，上传 OSS 与下载结果文件时不附带 Bearer Token；禁止跟随重定向和返回不可信存储地址。错误信息不展示 Token、签名音频链接或完整字幕。

## 6. Apple Podcasts 来源与边界

Apple 单集使用稳定的 `apple-podcasts-节目ID-单集ID` 归档标识，不因不同地区、分享标题或跟踪参数产生重复归档。正常 RSS 中，元数据 GUID 必须唯一命中发布方单集；没有 GUID 时只接受精确音源地址匹配，不使用标题猜测。非空 RSS 未命中、存在多个匹配、响应为空或格式错误均报错，不当作无字幕。

部分旧节目仍可在 Apple 打开，但发布方 RSS 只返回频道信息，已经没有单集条目。对此提供一个严格限定的兼容路径：响应完整、RSS 2.0 结构有效、频道信息完整、唯一 `atom:link rel="self"` 与 Apple 声明的订阅源一致（只允许同地址 HTTP 升级 HTTPS），并且没有任何 `item`；同时，Apple 当前单集页面必须精确核验节目及单集 ID、明确标为 `free`，且提供公开音源。仅满足这些条件，才报告「发布方 RSS 当前未列出单集」，交由已显式开启的 ASR 处理 Apple 指定的原集音源。未开启 ASR 时继续提示开启设置或导入字幕。

该分支不覆盖 RSS 网络错误、401/403、空响应、部分响应、损坏 XML、不完整频道、来源不一致、非空目录匹配失败或多义匹配。只有 Lookup 目录数据而没有当前单集页面核验，也不能进入此分支。空目录声明了新订阅源，或带有 `itunes:block=Yes` 时，不自动启动这个新增回退。`itunes:block` 是 [Apple 目录收录标记](https://help.apple.com/itc/podcasts_connect/en.lproj/itcb54353390.html)，不代表 HTTP 访问权限；已有单集能精确匹配且资源公开可读时保持原行为。

没有 RSS 的单集另行判断：只有准确的免费单集页面明确给出 `feedUrl: null`，且全部媒体项的 `transcriptInfo: null`，才把字幕发现途径视为明确缺失；若是普通公开音频文件，可以继续交由用户已开启的 ASR 处理。字段省略、未知结构、声明了字幕或只有 Lookup 元数据，都不能因此启动转写。

**免费可播放不等于可以直接转写。** 部分 Apple 单集没有 RSS，提供的是 FairPlay 保护的 HLS，而不是公开 MP3/M4A。例如《人间悲喜》001 瘦老头（一）（`1000775971124`）的公开清单声明了 `SAMPLE-AES` 与 `com.apple.streamingkeydelivery`。LinkRead 仅有界读取顶层清单作判断，不请求音频片段、密钥或许可证；App 显示「暂不支持此音源」，提供「查看来源」，不显示无效重试或建议开启 ASR。未确认保护但仍为 HLS 的音源也明确提示当前不支持流式转写。已有公开字幕的单集仍可直接读取字幕。保护标识参见 [Apple HLS 规范](https://developer.apple.com/streaming/hls-authoring-specification-for-apple-devices.html#content-protection)。

读取公开 `podcast:transcript` 的 VTT、SRT 或 Podcast JSON，保存源时间戳，字幕不得因重叠对谈而被自动去重。没有受支持的带时间戳字幕才抛出明确的无字幕状态；公开但损坏的字幕不会触发 ASR。Apple App 内可见的自动字幕不等于公开下载接口，本适配器不登录创作者后台或调用订阅接口。

音频从 Apple 公开单集元数据提供的发布方音源下载，逐次校验重定向、限制大小和超时；不采用 RSS 的过时 enclosure.length 判断完整下载。下载前及实际响应中识别 HLS 地址、媒体类型和清单文件头，不把播放清单保存为音频。下载成功后才发布缓存音频，未完成下载不进入 ASR。长度超出配置或未知时长时在下载前停止，长音频先检查 FFmpeg。ASR 沿用本页的分片、并发、缓存、临时上传和费用边界。

实现参考：[Apple RSS 要求](https://podcasters.apple.com/support/823-podcast-requirements)、[Apple 字幕说明](https://podcasters.apple.com/support/5316-transcripts-on-apple-podcasts)、[Podcast Namespace transcript 规范](https://github.com/Podcastindex-org/podcast-namespace/blob/main/docs/1.0.md#transcript)。

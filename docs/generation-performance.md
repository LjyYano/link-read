# 生成时延与批次恢复

## 1. 哪一部分慢

HTML 模板渲染是本地确定性工作；长时间等待通常位于字幕提炼、整稿标点校对和模型服务响应。自定义 API 当前使用完整 JSON 响应，只有整个批次返回并通过校验后才增加完成数。因此「未收到新结果」不代表模型停止工作，也不等于已经处理了某个百分比。

这次排查发现两个可优化点：特别长的单条 ASR 字幕会突破原有校对组批目标；已经有自然标点的文字仍需要模型完整复述。二者都可能拉长单次响应。实际供应商的排队、推理速度、限流也会影响时间，不能只根据界面等待时长判定。

## 2. 默认执行方式

新生成默认最多 **4 个模型请求**同时执行，整个文章共用同一个并发预算，不是每个线程池各并发 4 次。桌面多篇文章仍然串行。

提炼与基于原文的校对尽早并行，提炼成功后再并行整理摘要、导图和分类。校对工作池可以使用全部 4 个名额，所有阶段按等待顺序公平申请同一组名额，避免一个工作池连续抢占。校对结果在代码中按实际语义章节边界重组，校验每个原文字符和字幕索引。临时的原文校对上下文不作为真实摘要保存。

| 调整 | 当前行为 |
|---|---|
| 校对批次 | 文本块 JSON 从约 3000 字符降至最多 1800 字符；固定提示词、标题及 Schema 不包含在这个数字内 |
| 超长字幕 | 单条很长的 ASR 字幕在模型请求内部继续分片，尽量在句末或空白处分开；逐片校验后恢复原来的段落与字幕索引，不制造时间戳 |
| 无需改动 | 模型必须检查每个 index；标点已经自然时显式返回 `text: null`，由代码原样复用，不能省略片段 |
| 输出内容 | 需要改标点时仅返回该片完整文字；保留稀疏的小标题，不再要求校对同时产生逐段加粗、标红等装饰。已有正文强调与金句链路继续兼容 |
| 语义提炼 | 正常批次目标从 9000 降至 4500 字符；为保留准确引用索引，特别长的单条原字幕仍作为整体分析，不截断内容 |
| 重试 | 仅对逐字校验发现被改字的片段重试一次；请求超时不自动再发一轮 |

小批次会增加请求数与固定提示词开销，换来更短的单次输出和更细的完成反馈；在供应商限流或每次请求启动开销很大时，不保证总耗时缩短。后端内部 `generate_article(..., jobs=1)` 或 `jobs=2` 可用于开发时限制并发；这不是额外的桌面设置项。原始字幕、完整正文、章节、小标题、摘要、导图、关键词与金句均保留。

## 3. 失败后不从头开始

`.ai-checkpoints/` 仅保存通过结构与原文校验的批次。键包含模型、Provider、API 地址、输入、Schema 与缓存版本；复用时再次校验。改源文或模型配置不会错误命中之前批次。未通过逐字校验的响应不得进入成功缓存。

完整提炼结果先写 `note.json`，摘要/导图等成功后立即保存，即使另一个并行校对任务失败仍可复用。批次缓存不是部分发布的文章；全部必需阶段完成才生成最终 HTML。原始字幕不覆盖。

## 4. 查看真实耗时

成功生成的归档中，`.performance.json` 只记录数值，不保存 Token、提示词或模型原文。

| 字段 | 含义 |
|---|---|
| `wall_seconds` / `html_seconds` | 本次总耗时 / 本地 HTML 渲染耗时 |
| `model_calls` / `cache_hits` | 实际模型请求数 / 已验证批次缓存命中数 |
| `concurrency_limit` / `max_concurrency` | 配置并发上限 / 实际观测到的并发峰值 |
| `model_seconds_sum` / `model_seconds_max` | 模型调用累计耗时 / 最慢一次调用耗时，不含在本机等待并发名额的时间 |
| `queue_seconds_sum` | 所有请求等待本机并发名额的累计时间，不是供应商排队时间 |
| `prompt_chars_sum` / `prompt_chars_max` | 提示词字符总量 / 最大单次字符数，不含独立发送的 Schema |
| `output_json_chars_sum` / `output_json_chars_max` | 返回 JSON 的序列化字符总量 / 最大单次字符数，均不是 Token 计费值 |

并行请求的累计时间可能大于实际总耗时，不要将它们相加。主任务卡显示已完成批次数，调度序号仅保留在详情中；进度条的流动高亮表示仍在运行，不会随计时器虚增完成度。

## 5. 验证边界

离线回归检查超长字幕、JSON 转义字符、无损重组、原索引与时间戳、`null` 的明确覆盖、小标题保留、真实并发峰值、公平排队、超时不自动重发、失败恢复与缓存隔离。使用模拟 Provider 验证请求大小和调度行为，不将模拟耗时当作 Codex、百炼或其他真实供应商的提速承诺；本次没有为性能测试调用用户的付费模型。

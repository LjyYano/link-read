# 1. 桌面 AI 整理流程

桌面应用通过自己的 `linkread_desktop` 后端执行提取、AI 整理、校对和阅读页生成，不调用 `linkread` CLI。用户在设置中选择 Codex、Claude Code 或自定义 OpenAI 兼容 API，再提交视频、播客链接或本地字幕。

本地字幕解析与已有资料的离线阅读不需要模型。点击“生成文章”或明确重新整理时，才按当前 Provider 发起模型请求。

# 2. 数据与编排

| 数据 | 用途 |
| --- | --- |
| `TranscriptDocument` / `transcript.json` | 保存完整原文、来源与原始时间戳，不被 AI 覆盖 |
| `NoteDocument` / `note.json` | 保存分析、Provider 信息、完整原字幕及校对段落 |
| `ChunkInsights` | 模型仅返回分块内部字幕索引，程序映射回原文与时间 |
| `.ai-checkpoints/` | 保存经过结构和原文校验的成功批次，按配置隔离复用 |
| `article.html` | 必需阶段成功后生成的离线阅读页 |

`generation.generate_article()` 是后端内部编排入口。默认生成批次上限 4500 字符、单次模型超时 300 秒、全局并发预算 4。阶段可并行，但合并结果保持原字幕顺序；更详细的批次和校对说明见[生成时延](generation-performance.md)。

`desktop.py` 负责 JSON Lines 接口、任务进度、归档访问和替换保护；`generation.py` 不依赖命令行框架。前端与原生层始终传入当前 Provider，本地字幕不能绕过 AI 生成链路。

# 3. Provider

- **Codex**：使用本机可信的 Codex CLI 和已有登录；以 read-only sandbox、结构化输出和独立临时目录执行，不允许模型写入项目。
- **Claude Code**：使用 bare API 模式和合法的 `ANTHROPIC_API_KEY` 等 API 认证，不读取订阅 OAuth；禁用工具调用和会话保留。
- **自定义 API**：使用 OpenAI 兼容 Chat Completions。远程地址必须为 HTTPS，loopback 可用 HTTP；禁止跟随跨域重定向，错误和日志不包含密钥或完整字幕。

桌面密钥按设置流程保存在本机应用数据目录的私有文件，权限为 `0600`，并非加密存储；不会写入项目归档或浏览器 localStorage。详情见[桌面说明](../desktop/README.md)。调用第三方模型会发送相应字幕内容，用户需要自行确认内容权利、服务条款与费用。

# 4. 原文与恢复验证

- 模型引用必须落在有效字幕索引范围，章节按原顺序排列；时间戳由程序读取原字幕，不能由模型猜测。
- 完整阅读正文覆盖全部字幕；去除 Unicode 标点与空白后，校对段落必须与原文逐字一致。不符时重试，仍不符则保留完整原文并显示说明。
- 小标题是 AI 生成的结构，不冒充原文说过的话。金句来自可核对的连续原文，不为了数量凑内容。
- 成功的字幕、笔记及批次可复用，错误不会把不完整结果发布为完成文章。重新整理采用隔离工作区，失败保留旧归档。
- 旧笔记即使没有全文校对字段也能离线渲染；是否重新生成由用户明确操作决定。切换 Provider 不把另一模型的半成品冒充新结果。

# 5. 验证范围

离线测试使用模拟 Provider 验证引用、原文完整性、缓存、任务恢复和导出，不代表真实模型的响应速度或输出质量。AI 摘要仍需结合原文判断。

无字幕音源可由用户显式开启 ASR，见[预览与语音识别](preview-and-asr.md)。模型 CLI 的安装、登录、网络和实际付费服务调用需在使用环境中分别验证。

# 阅读页封面与紧凑词云 设计

日期：2026-11-28。范围：阅读页模板（`src/linkread_desktop/renderers/`）、封面来源解析、原生阅读页的图片策略、离线测试与文档。

## 意图

阅读页在应用内、HTML 导出和静态站点导出里是同一份 HTML。现在标题区只有文字，首页卡片却有封面；关键词页已有螺旋排布，但一篇文章通常只有 7–14 个短语，排出来像居中的几行彩色字，不像词云图。

目标：

- 有封面的文章在标题区显示封面。
- 关键词页变成紧凑铺满、大小对比更强的横排词云。
- 旧文章在下次重建阅读缓存后直接用上，不需要重新生成，也不调用模型。

## 目标、非目标、反目标

目标：

- 封面在应用内、导出的 HTML、静态站点导出的文章页里都能显示；有本地封面的文章离线也显示。
- 没有封面或封面加载失败时，标题区与现在完全一样，不留占位或破图。
- 关键词仍是可点击、可用键盘操作的搜索按钮，顺序和文字不变。
- 词云排布是确定性的：同样的词和宽度，每次排法相同。

非目标：

- 不改首页卡片和静态书架的列表结构。
- 不改 `note.json`、`transcript.json`，不引入词频，不调用模型。
- 不改 Markdown 导出。
- 打开文章和重建缓存时不联网下载封面，只用已保存的内容。
- 关键词不竖排，不做云朵形状遮罩。

反目标（做成了也算失败）：

- 封面缺失或离线时出现破图、空框，或页面加载后跳动。
- 窄窗口里封面把正文推到很靠下。
- 词云里词语重叠、被截断，或小到点不中。
- 放宽图片策略时放行了三个图片域名以外的来源，或放行了图片以外的资源类型。
- 把本机路径或应用来源泄露给图片 CDN。

## 约束

- 阅读页必须保持单文件、离线可用：不引用 CDN 脚本或字体。
- 应用内阅读页的响应头带有内容安全策略，目前是 `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:; base-uri 'none'; form-action 'none'`，即图片只允许内嵌数据。
- 封面网址的白名单由 `metadata.thumbnail_url()` 决定：`i.ytimg.com`、`*.hdslb.com`、`*.mzstatic.com`，统一为 HTTPS。首页的图片策略放行的也是这三个域名。
- 「在浏览器打开」和「HTML 导出」用的是重建后的阅读缓存 `.reader.html`，不是归档里的原始 `article.html`。
- 打印只输出正文；Aa 的字号、行宽、行距只作用于正文和简介。
- 冻结的 sidecar 不含 Python 源码，Python 侧的渲染变化要提升 `reader_cache.CACHE_VERSION`。

## 方案

### 封面如何进入页面

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| 只写远程网址 | 最简单，但应用内被图片策略拦截，离线也没有 | 不采用 |
| 写应用私有协议地址 | 应用内离线可用，但导出后在浏览器里是坏链接 | 不采用 |
| 有本地封面就内嵌，否则用白名单内的在线网址 | 本地封面真正离线并随导出带走；旧文章联网时显示；图片策略只需增加首页已信任的三个域名 | **采用（你已确认）** |

### 封面位置

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| 标题左侧，两栏 | 正文仍在靠上位置；视频 16:9，播客方形 | **采用（我的决定）** |
| 标题上方通栏大图 | 更抢眼，但把正文推低约 400px，方形播客封面会被裁切 | 不采用 |
| 标题前的小图标 | 太小，认不出封面 | 不采用 |

### 词云排法

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| 紧凑横排 | 铺满卡片、大小对比强；短语和中文都好读 | **采用（你已确认）** |
| 紧凑横排加部分竖排 | 最像经典词云图，但竖排短语难读 | 不采用（你选择不竖排） |
| 按重要性变大的标签块 | 更像标签云，不像文字云图 | 不采用 |

## 设计

### 封面

- **来源顺序**（与首页卡片一致）：

  1. 归档里有校验过的本地封面（`cover.jpg`、`cover.png`、`cover.webp`、`cover.gif`）且不超过 1 MiB 时，内嵌为 `data:` 图片。更大的本地封面改用在线网址。
  2. 否则用在线封面网址：本地字幕文章用它关联来源的封面，其他文章用保存的来源封面网址。网址必须通过 `thumbnail_url()` 白名单。
  3. 都没有时不显示封面。

- **渲染入口**：`render_html()` 新增可选的封面参数，并在渲染时再校验一次。只接受两种值：`data:image/(jpeg|png|gif|webp);base64,` 加合法的 base64，或 `thumbnail_url()` 原样返回的 HTTPS 网址。其余一律当作没有封面。

- **标记与布局**：有封面时，标题区 `<header class="hero">` 增加 `has-cover`，并插入一个 `<img class="article-cover">` 作为第一个子元素。标题、元信息、阅读操作按钮保持原有顺序，用 CSS 网格排到封面右侧。视频用 16:9，播客用 1:1，带宽高属性以避免加载时跳动。窄窗口缩小封面，仍放在标题左侧。

- **图片属性**：`alt=""`（标题就在旁边，不重复朗读）、`decoding="async"`、`referrerpolicy="no-referrer"`。

- **加载失败**：`reader.js` 监听封面的 `error` 事件，移除 `has-cover` 和图片，标题区回到无封面的排版。

- **调用方**：

  - 生成文章时写入归档的 `article.html`：先等封面下载（沿用现有的 12 秒预算），再渲染，这样归档里的页面也带封面。
  - 重建阅读缓存 `.reader.html`：只用已保存的封面文件和已保存的网址，不联网。
  - 静态站点导出的文章页：同样带封面。静态书架首页不动。
  - 字幕快照预览：不带封面。

- **原生图片策略**：`img-src` 从 `data:` 改为 `data: https://i.ytimg.com https://*.hdslb.com https://*.mzstatic.com`，其余指令不变。

- **打印**：不打印封面。

- **缓存版本**：`CACHE_VERSION` 从 12 提升到 13。

### 词云

- **字号**：沿用现有的 `--weight` 机制，把曲线调陡。首位约 56px，末位约 15–19px，长词继续按长度缩小。
- **排布**：从中心沿扁椭圆向外找位置，词间距比现在更紧。全部放完后按实际外框裁剪高度并居中。
- **铺满**：如果词云宽度不到卡片宽度的约 85%，整体等比放大字号后重排。最多两轮，上限约 1.35 倍，让只有 7–8 个词的小词云也能撑起卡片。
- **兜底**：超过 52 个词或放不下时，回到现在的流式排布。没有 JavaScript 时同样是流式排布。
- **悬停、聚焦、点击搜索、减少动态效果**：行为不变。

### 可测性

排布算法是纯计算，不碰 DOM。把它放到独立的渲染脚本 `keyword-layout.js`，像 `reading-position.js` 一样同时供页面内联和 Node 测试加载。`reader.js` 只负责测量文字和应用位置。

## 测试

- **Python**：

  - `render_html()` 的封面校验：合法的 data 图片和白名单网址被采用；HTTP、其他域名、`javascript:`、超大或非法 base64 被丢弃。
  - 没有封面时页面里没有 `<img>`，标题区不带 `has-cover`。
  - 本地封面内嵌：合法的 jpg、png、webp、gif；超过 1 MiB、缺失或符号链接时回退到在线网址。
  - 重建阅读缓存时使用本地封面或已保存的网址，全程不发网络请求。
  - 生成文章时 `article.html` 带封面；没有封面时不带。
  - 静态站点导出的文章页带封面。
- **Rust**：单元测试钉住阅读页图片策略的 `img-src` 列表，其余指令保持不变。
- **共用用例**：新增 `tests/fixtures/cover_hosts.json`，Python 的 `thumbnail_url()`、前端的 `thumbnailSource()`、Rust 的图片策略三处都读它，防止白名单与图片策略脱节。
- **Node**：`keyword-layout.js` 在多种词数和宽度下不重叠、不出界，同样的输入结果相同。
- 现有测试全部保持通过，包括「关键词注入不能产生 `<img>`」那条。
